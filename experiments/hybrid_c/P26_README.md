# P2.6: C-only, подготовка

Технический режим готов, коммерческая проверка перед запуском: FAIL.
На локальных подменённых решениях обнаружены:
1. «Куплю, если можно вернуть деньги» + action=END + «Тогда оформляем заявку.» проходит.
2. «Сколько длится обучение?» + ASK «Что вас мотивирует учиться?» проходит.
3. «Давайте закончим, мне сейчас неудобно» + ASK проходит.
Историческое утверждение «Это условие закреплено в договоре» блокируется;
явное условное согласие с CLOSE блокируется; обычное уважительное END разрешено.
Это проверка поведения валидатора, не предсказание реальных ответов DeepSeek.
Перед расходами устранить эти общие несоответствия фразы/действия/границ и повторить офлайн-проверку.
Движок и промпт на этом шаге не исправлялись; production не изменён.

Контекст читается только из сохранённого P23 inputs.json: turns/facts/approved_claims
дословно совпадают с обоими прежними входами. Экспертные ответы и будущее не загружаются.
Все пять точек сохранены. A/B повторно не исполняются и не перезаписываются.

После устранения блокирующих замечаний и отдельного разрешения:

```powershell
.venv\Scripts\python.exe -m experiments.hybrid_c.c_only --out work/p26-private/live-01 --allow-paid --allow-private-transcripts --max-calls 10
```

Без флагов --allow-paid/--allow-private-transcripts создаётся только офлайн-пакет.
5 первичных, максимум 10 обращений, до одного recovery на случай. Общий Budget и Journal.
Реестр и блокировка в work/p26-private; новая папка не обходит защиту повторного запуска.
Тот же механизм разрешения повторных расходов, что P23/P25: --authorize-repeat p23-real-sales-pilot-v1
только по отдельному явному разрешению. --resume сохраняет лимит и не повторяет неопределённые вызовы.

Модель проверяется на совпадение с журналом P23, max_tokens=3000, temperature=.2, thinking disabled.
Одинаковая история не означает одинаковый полный prompt: C имеет новый контракт и проверки.
Запуски разнесены во времени; alias провайдера мог измениться, кэш и нагрузка другие.
Это пять раскрытых регрессий, а не независимый holdout. Честно сравнивать замороженные конечные системы,
не приписывать разницу одному компоненту архитектуры.

После запуска эксперту передать только reviewer/answers.md и reviewer/assessment_template.csv.
Критерии прежние, поля оценок пустые. Нет прошлых оценок/ответов A/B/будущих реплик.
Не раскрывается внутренний reason валидации или исходный blocked ответ как успешно показанная фраза.
До фиксации новой оценки сравнение качества с A/B не выполняется.

## Обновление P2.6.1 — готовность к ограниченному измерению: PASS

Три ранее описанных блокирующих случая исправлены в experimental guards.py.
Проверяется речевое действие конечной фразы, а не только action; END требует прощания без
вопроса/оформления/побуждения продолжить. Условие покупки выделяется только при наличии
сигнала готовности и условной связки; обычное гипотетическое «если» не блокирует продажу.
Подтверждение условия консервативно требует текстовой поддержки approved_claims.
Прямой предметный вопрос (в том числе сохранённый open) имеет приоритет над диагностикой.
Разрешено ограниченное уточнение продукта/формата с объяснением необходимости для ответа.
Временная недоступность не допускает записи event=declined или факта отказа от покупки.

38 целевых и 243 полных теста прошли. Старый тест сохранения открытого вопроса обновлён:
после нового вопроса менеджера C предлагает проверку исходного вопроса, а не ещё одну диагностику.
Память и её атомарность сохранены. P23, оценки, production, лимит 10 и транспорт не менялись.

Ограничения: локальные речевые признаки и темы не являются универсальной семантической проверкой.
Возможны незнакомые перефразы, неверное разрешение косвенных ссылок, ложные блокировки при
перефразированном approved_claim и неверно выбранное моделью основание уточнения. Историческое
условие может оставаться открытым после нераспознанного изменения решения. Положительные тесты
не доказывают полную безопасность; PASS означает готовность ограниченного исследовательского
запуска с последующей экспертной оценкой, а не допуск в живые продажи.
Команда C-only выше сохранена. Запускать только после отдельного разрешения. API в P2.6.1 не вызывался.
