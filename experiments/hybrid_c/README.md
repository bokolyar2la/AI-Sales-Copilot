# Hybrid C — эксперимент P2.5

Production и UI не переключены. `engine.py` реализует компактный Pydantic-контракт,
один запрос через существующий CompatibleProvider/ObservedProvider, максимум одну коррекцию.
Результат сохраняется через тот же benchmark и атомарный Journal: сырой JSON, usage, latency,
причины отклонения, итоговая фраза, обновлённая сессия. Нет постоянного второго оценщика-LLM.

Память остаётся в session.facts/hypotheses/dialogue_state. Используются Fact, HypothesisUpdate,
DialogueEvent, apply_hypotheses, update_state, uid/now. Нового хранилища нет. В экспериментальном
runner сессия после шага записывается в результат; приложение пока её не использует.
Дельта атомарна, проверяется последняя реплика и точная цитата, категория замены факта.
Отвергнутые гипотезы сохраняют историю. События открытых вопросов/возражений не закрываются советом ИИ.

## Проверка и ограничения прототипа

Проверяется конечная фраза, не только reason. Условное согласие, распознанное в истории,
консервативно требует фиксированного шага проверки документов. Продуктовый риск требует
дословного approved_claim с реальным ID либо безопасной фразы проверки. Это не полный
семантический валидатор: непрямые перефразы могут быть пропущены, а корректные — заблокированы.
Повторные вопросы сравниваются нормализованно, смысловые повторы ещё не гарантированно выявляются.
Распознавание отказов/условий лексическое. Любое историческое «если» может вызвать лишнюю блокировку;
автоматического доказательства выполнения условия пока нет, даже при наличии другого approved_claim.
После двух нарушений ответ blocked, исходные варианты сохранены, выдуманной успешной фразы нет.
Модель отвечает за выбор релевантного препятствия и новые события; качество без реального теста не доказано.

## Запуск

Из корня проекта, без API:

```powershell
.venv\Scripts\python.exe -m experiments.hybrid_c.run --out work/p25-private/offline-02
```

После отдельного разрешения платного A/B/C на пяти раскрытых регрессионных точках:

```powershell
.venv\Scripts\python.exe -m experiments.hybrid_c.run --out work/p25-private/live-01 --allow-paid --allow-private-transcripts --max-calls 25
```

15 базовых вызовов, максимум 25: A до 2, B 1, C до 2 на каждую из пяти точек.
Все варианты используют общий Budget и журнал. Повтор неизвестного оплаченного запроса не выполняется.
Для продолжения той же папки --resume; версия кода/контекста/варианты/лимит должны совпасть.
Реестр изолирован в work/p25-private; использует существующий механизм защиты P23 и его ключ
`p23-real-sales-pilot-v1` для явного --authorize-repeat. Это технический ключ механизма, не продолжение P23.
В папке C есть отдельные хеши контракта и промпта; A/B не удалены и работают как раньше.
Не применять --authorize-repeat без отдельного разрешения повторной оплаты.

Офлайн-запуск создаёт 15 отсутствующих ответов, не симуляцию коммерческого качества.
Для слепой оценки общий стенд выдаёт response_id Rxxx и private_mapping.json; mapping не передавать эксперту.
Пять раскрытых точек — только регрессии. Проверка превосходства требует новых звонков и независимой разметки.
Не включать work/p25-private и исходные реальные транскрипты в Git.
