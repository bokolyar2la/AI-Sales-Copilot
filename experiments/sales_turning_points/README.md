# Sales Turning Points — локальный исследовательский корпус

24 черновые контрольные точки, по четыре из шести PDF. Production не изменён.
Это материал для экспертного исследования, не эталон качества и не обучающая выборка с готовыми оценками.

## Хранение

Весь материал реальных звонков находится в `private/`, исключённом из Git:
- `call_1.json` … `call_6.json`: исходное извлечение PDF, включая персональные сведения; не публиковать.
- `transcripts_redacted.json`: обезличенные сегменты, исход звонка отдельно от подтверждения оплаты.
- `corpus.json`: история до сигнала, черновая разметка, фактическое продолжение и наблюдаемый ответ.
- `pattern_map.json`: карта кандидатов в положительные/отрицательные/смешанные примеры.
- `offline_inputs.json`: экспорт для локального стенда, без будущих реплик; создаётся командой ниже.

Исходные PDF остаются в Downloads пользователя. При переносе можно положить их в `private/sources/`.
Порядок call_1…6: Управление командой 2; Директор по логистике; Бухгалтер Базовый;
Excel Prо; Директор по строительству; Операционный директор.
Сами PDF, извлечения, обезличенный корпус и результаты не включать даже в публичный PR.

## Источники и смысл разметки

Каждый сегмент сохраняет страницу начала, время, номер говорящего, SHA-256 исходного PDF
и SHA-256 исходного текста сегмента до редактирования. Нумерация сегментов локальная.
История — полный префикс транскрипта. Ничего из последующей реакции клиента не подаётся модели.
`observed_continuation` содержит фактическое продолжение; отсутствие реакции означает отсутствие записи,
а не согласие. `confirmed_goal` — проверяемая черновая интерпретация с источниками.
`CONFIRMED` в фактах означает только наличие текста в PDF, а не проверенную достоверность сведений.
Все продуктовые утверждения менеджера исторические и неподтверждённые. `approved_claims` всегда пуст.
Ни один звонок не обозначен независимо подтверждённой оплатой.

Разметка ролей основана на метках PDF. Есть смешанные и неизвестные говорящие; аудио не проверялось.
Автоматически скрыты имена, контакты, числовые значения и часть сведений оформления.
Числа скрыты консервативно, включая часть полезных количественных деталей: восстановление допустимо
только после ручной проверки необходимости. Обезличивание не считается окончательно проверенным.
Все 24 точки требуют экспертного подтверждения и проверки приватности перед внешней отправкой.
Неоднозначные смешанные сегменты требуют ручного разделения с сохранением источника.

## Проверки и офлайн-адаптер

Из корня проекта в Windows:

```powershell
.venv\Scripts\python.exe -m experiments.sales_turning_points.corpus --export-offline
.venv\Scripts\python.exe -m pytest experiments/sales_turning_points/test_corpus.py -q
```

Валидатор проверяет полную историю, ссылки, отсутствие будущих фактов, реальность продолжения,
роли цитируемых говорящих, отсутствие одобренных исторических условий и автоматических оценок.
20 точек совместимы по структуре с `experiments.sales_benchmark.run.validate/inputs`;
4 заблокированы из-за неизвестного говорящего в префиксе. Экспорт не является разрешением API.
`benchmark_case` создаёт `origin=historical`, `benchmark_eligible=false`.
Можно передать эти случаи в существующий `run(..., mode='missing', cases_override=...)` для
локальной подготовки пар без вызовов модели. Платный режим здесь не реализован.
`paired_inputs` предусматривает A/B/C: для C подготовлен только контракт входа, третий движок не создан.
При сравнении нужно отдельно сохранять профиль валидации каждого варианта, в частности schema_only для B.
Разбиение будущей выборки делать по звонкам, не по точкам одного звонка, чтобы исключить утечку.

## Обязательная экспертная работа

Подтвердить цели и активные препятствия, допустимые семейства действий и отрицательные примеры;
исправить ASR/роли; проверить обезличивание; оценить конкретные реплики отдельно от исхода звонка.
Окончательные оценки не проставлены. Кандидат в положительный пример не означает одобрение всех
слов менеджера: например, ответ на цену полезен как действие, но историческая цена не утверждена.
Контрольные точки охватывают остановку диагностики, объяснение новичку, аргументацию по запросу,
исправление гипотезы, условную готовность к оформлению и уважительное завершение контакта.
